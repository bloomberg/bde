BDE Metrics Grafana Dashboard

The page describes the use of the BDE Metrics Grafana Dashboard. This dashboard captures three metrics from four thread enabled objects within the BDE library. Overall, there are five valid combinations of metric and producing component, each with a panel on the dashboard. Note that if the filtered dataset does not include a particular combination, the panel will appear empty and have the text “No data”. The dashboard presumes the availability of standard GUTS tags and some additional tags provided by BDE and the BAS infrastructure. These tags allow for filtering the presented data sets and also grouping to make surveying the data easier. These filters and the grouping are at the top of the dashboard.

BDE Metrics

These are metrics published by thread-enabled objects within the BDE libraries.

Name

Type

Description

Observation

bde.backlog.g

Gauge

A snapshot count of the number of pending jobs minus number of “idle” threads in the thread pool. Value may be negative.

On a periodic timer cycle only.

bde.startlag.g

Gauge

A snapshot of the delay time in starting the next pending event, measured in fractional seconds.

On a periodic timer cycle only.

bde.usedcapacity.g

Gauge

A snapshot of the number of pending jobs divided by queue capacity.

On a periodic timer cycle only.

Filters on Tags from GUTS and BAS

Each filter allows selection of “all” (exluding ServiceName) or a set of values. The filters can be searched by typing partial values. Note that a user must set one or more values for the ServiceName filter (the dataset would otherwise be too large).

GroupTags

The GroupTags allows for aggregating the dataset by tag value. The resultant value is the maximum value at each timestep for the aggregated tags. The list of available tags is dependant on the producing processes and is generally too numerous to include here. A good starter setting for GroupTags is “host” and “identifier”. This groups the data by the producing host and the unique identifier for the object instance in the application (e.g., a set name or a generated identifier like “ftp.1” for the first created unnamed bdlmt::FixedThreadPool). Note that the order the tag names are selected is the order the tag values are appended to produce the label for the timeseries.
