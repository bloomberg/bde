BDE Metrics GUTS Integration

For applications using the BAS service framework, BDE metrics should be enabled and delivered via GUTS automatically. For application owners not using the BAS framework though, a bit of extra work (described below) is required to enable BDE metrics to be delivered via GUTS. Information on BDE Metrics can be found in BDE Metrics Grafana Dashboard.

Integrating the publication of BDE Metrics into existing GUTS publishers is a three step process, assuming access to a GUTS metrics manager (e.g., the default manager). This article assumes you are familiar with enabling and configuring your application for GUTS (please reach out to the GUTS team for more information).

First, create a bdlm metrics adapter using a GUTS metrics manager:

guta::BdlmMetricsAdapter adapter(gutz::DefaultMetricsManager::instance(),
                                 "applicationName",
                                 "functionalIdentifier");

The “applicationName” is the GUTS namespace to which you are publishing, and the “functionalIdentifier” is a prefix, which may be empty, for the “identifier” tag provided to GUTS. Note that for BAS services, an empty value (“”) is supplied for the functional identifier.

Then, register the adapter to provide the “handshake” between the metrics in the BDE components (e.g., bdlmt::FixedThreadPool) and the adapter which forwards to GUTS:

bdlm::MetricsRegistry::defaultInstance().setMetricsAdapter(&adapter);

Finally, as part of application shutdown, deregister the adapter:

// ... application shutdown ...

bdlm::MetricsRegistry::defaultInstance().removeMetricsAdapter(&adapter);
